Architecture overview

The protocol is a set of contracts on the HyperEVM L1 that uses Hyperliquid's HyperCore precompiles for pricing and bridging. This page maps the contracts and how they fit together.

Contracts (HyperEVM)

  • Exchange: the main trading contract. Tracks user balances, opens and closes positions, settles PnL, manages the payout queue, holds the LP balance. Opens and closes can only arrive through the batch executor; withdrawals and maintenance calls can come from anyone.
  • BatchExecutor: entry contract for batched intents. It accepts batches only from Papertrade's relayer keys, then unpacks N user intents and dispatches them to Exchange.
  • PaperToken, PaperStaking, PaperTokenomics: the PAPER token, staking contract, and mint-rate calculator. At launch PAPER is non-transferable apart from staking and unstaking.
  • SessionKeyManager: registers and validates session keys, so a user can authorise a scoped key once and sign individual intents off-chain without a wallet popup. Registration is submitted through the relayer; revocation is a direct call from the user's wallet.
  • PriceOracle: wraps the BBO/Mark/Oracle precompiles for in-contract reads.
  • DepositProxyFactory + Create2DepositProxy: derive per-user deterministic deposit addresses; bridge incoming USDC from HyperCore into the Exchange.

Precompiles (HyperCore)

  • BBO 0x...080e: best-bid/ask read; the protocol's execution price.
  • Mark 0x...0806: Hyperliquid's "fair" mark; read for analytics and future cross-checks.
  • Oracle 0x...0807: validator-median external reference; read for forward-compat.
  • CoreWriter: the bridge interface. Used by Create2DepositProxy to push USDC from the user's proxy Core account into the Exchange's HyperCore account, and by Exchange.withdrawToCore to move funds back to the user's Core spot account.

A trade end-to-end

A signed user intent hits the relayer, then the authorised BatchExecutor, which unpacks it and calls Exchange.openPositionBySig (or close, staking, etc). Exchange reads the BBO precompile through PriceOracle for the execution price, settles PnL against the LP, updates the user's internal balance, and mints PAPER on realised losses through PaperTokenomics. Multiple users' intents can be batched into a single EVM transaction; each one is dispatched and settled independently inside BatchExecutor.

Frontends

Papertrade's relayer submits every open and close. A different frontend can produce compatible user signatures and send them through the relayer, but it can't submit opens or closes to the contracts directly.
